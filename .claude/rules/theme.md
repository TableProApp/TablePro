# Theme

## What a theme colors

- **A theme colors content and the window backdrop, never chrome.** Content is every code view, the data grid, value text and wells, value trees, diffs, record tables, diagrams, charts, and the states that stand in for any of them. Chrome is controls, Accent, Highlight, the sidebar, inspector frame, toolbar, titlebar, tab strip and bars, Settings, Welcome, the connection form, sheet and popover chrome, and SwiftUI `List`, `Form` and `Table` backgrounds. `NSApp.appearance` is the only lever on chrome.
- **Chrome never reads a slot.** It asks `ThemeBackdropState.isThemed(in:scope:)` or `isThemed(highContrast:scope:)` whether the backdrop behind it is themed, and answers with a system style:
  - A bar over a pane takes `.paneBarBackground(_:ignoresSafeAreaEdges:)` with the native style it drew before (`.bar` by default, or a flat `controlBackgroundColor` or `windowBackgroundColor`). It draws that style while the backdrop is unthemed and nothing while it is themed, because a material over a themed pane reads as a system band. No edges by default, so a top bar never reaches under the toolbar.
  - A bottom status bar drops its material through `DetailPaneStatusBarMaterial`, which sets `statusBarDrawsMaterial(_:)` for `StatusBarChrome`.
  - The editor tab strip track draws `secondarySystemFill` over a themed backdrop on macOS 26 and later, where the track sits on the theme's window color, and its unthemed fill otherwise. Never a palette color.
- **A code field takes the editor theme wherever it appears.** Startup Commands, Pre-Connect Script, a favorite's query, Rewind, Agent SQL, the deep-link Startup SQL and the tunnel command preview wear `editor.*`; the form or sheet around them stays system.
- **The slot family follows what the surface shows.** Code, values, value trees and wells: `editor.*`, with tree tones from `editor.syntax.*`. Records, schema objects, diagram nodes, chart plots and states that stand in for a grid: `dataGrid.*`. Diff rows: `dataGrid.inserted`, `modified` and `deleted` over the editor background and text. A region behind panes: `window.background`. Identity, severity and status hues stay system.
- **Every site passes what it draws natively.** A themed call site names a slot and, as its fallback, the exact system color or style it drew before, so while the active theme leaves the slot out the pixels are an unthemed app's. A default changes only on purpose, named in the PR and the CHANGELOG.

## The model: `TableProTheme`

- **`TableProTheme` (`Packages/TableProCore/Sources/TableProTheme`) is the theme model, Foundation only**: `ThemeSlot`, `ThemeColor` (RGBA8 with compositing, mixing and WCAG contrast), `ThemeDefinition`, `ThemeFileFormat`, `ThemeLoadError`, `ThemeResolver`, `ThemeOrdering`, `DefaultSyntaxPalette` and `ThemeFileImporter`. AppKit and SwiftUI stay in `TablePro/Theme`, so the iOS app can adopt the package. Its tests are `TableProThemeTests`, under `swift test`.
- **`ThemeSlot` is the one registry.** The decoder, the encoder, the theme editor and the VS Code mapping enumerate it. Each slot declares `group` (its file key), `section` (where the theme editor lists it), `label`, `accessibilityLabel` (unique, one whole localized phrase), `yieldsToIncreasedContrast`, `requiresOpaque`, `offersOpacity` and `fallback`, each an exhaustive switch, so a new slot cannot ship without every decision. A slot exists only with a reader: nothing checks for one no view reads, so removing a slot's last reader removes the slot.
- **Every slot is optional, and `fallback` decides what an unset one draws.** `ThemeDefinition.value(for:highContrast:)` returns `.themed`, `.system(slot)` or `.defaultSyntax(slot)`:
  - `.system`: the slot's native color, `ThemeSlot.nativeColor`.
  - `.defaultSyntax`: the same appearance's `DefaultSyntaxPalette` color (Xcode's Default, with its high-contrast variant). Syntax has no system color.
  - `.slot(other)`: the other slot's theme color, else native. The operator follows `editor.text`; the bools and the header text follow `dataGrid.text`.
  - `.derived(base:rule:)`: built from the base while the theme sets it, else native. The alternate row is the grid background mixed 4% toward the grid text, or toward black in a light theme and white in a dark one when the text is unset. The header background equals the grid background.
  - `.paired(with:fallback:)`: `dataGrid.selectionText` draws a theme color only over a themed `dataGrid.selection`, its own color or else the grid text. Under AppKit's selection it stays native, white text included.
  - A rule names only slots that fall back to the system themselves, so resolution never chains.
- **`isOverridden(_:)` means the slot draws a theme color, set or derived.** Every carrier asks it before it swaps a native drawing path. Only the theme editor asks `hasExplicitColor(_:)`, which means the file writes the slot.
- **Default Light and Default Dark set no slot.** They draw a native app plus the default syntax palette. A duplicate of one carries no overrides either, so it keeps the high-contrast syntax.
- **Opaque slots.** `requiresOpaque` holds `window.background`, `editor.background`, `dataGrid.background` and `dataGrid.headerBackground`: the codec and `value(for:highContrast:)` drop their alpha, so no fill shows the desktop through the window. `offersOpacity` marks the washes drawn over content (selections, current line and statement, invisibles, alternate row, change tints); only their wells offer opacity. No slot has both.
- **Schema policy.** Adding a slot bumps `ThemeSchema.current`. The decoder keeps reading every format from 3 up and refuses a newer one, and an unknown key stays an error: a file is refused rather than loaded without colors its author wrote. The bump also renames the sync content kind (Sync, below).
- **Import.** `ThemeFileImporter.importTheme(at:)` checks the size before it reads a byte, reads a TablePro theme (a numeric `schema`) or a VS Code color theme (`colors`, `tokenColors`, `include`, `settings` or VS Code's `$schema`), and mints a fresh id every time: a file's id says nothing about which theme on this Mac it is. A VS Code `include` never leaves the chosen file's folder. `ThemeSlot.vscodeSources` is an exhaustive switch, and a slot the fallback rules derive the way VS Code paints it stays unset.

## Reading colors in the app

- **`ThemeScope` is where a carrier reads.** `ThemeScope.live` forwards to `ThemeEngine.shared` and `AppEvents.shared.themeChanged`. `ThemeScope.fixed(_:)` draws one definition in both appearances on its own `ThemeSource` and never reports a change; a new definition is a new scope. Only the theme editor preview passes a fixed scope. A scoped carrier reads `activeTheme`, `palette`, `resolved` and `changes` through its scope, never through `ThemeEngine.shared`. The SwiftUI modifiers read the engine.
- **Two color tiers.** `palette[slot]` and `palette.color(_:otherwise:)` are dynamic colors over the scope's theme pair; use them wherever a view holds a color. `palette.color` returns a new object on every call, so never compare it to skip a write. Each `ThemeSource` names its colors apart, so a fixed scope's color never equals a live one. `resolved[slot]` is the active theme's color or the system color object itself, never a flattened copy; bake it into a `CGColor` only inside the drawing view's appearance (`resolved.cgColor(_:otherwise:in:)`), and check `resolved.isOverridden(_:)` before replacing a native drawing path (row selection, caret, header).
- **The carriers.** SwiftUI: `.themeBackground(_:native:)`, `.themeForeground(_:native:)`, `CodeWell`, `.valueWell(clipsContent:)`, `TextValueEditor(style: .code)`, `.gridStandInBackground(isActive:)`, `.valueStandInBackground()` (a state that takes the place of a value's tree or text, on `editor.background`) and `.geometryMapWell()` (the map pane's well). AppKit, each taking a `scope:`: `ThemeTextViewStyle` on an `NSTextView`; `ThemeTableChrome` (`.records` or `.code`) on a content `NSTableView` or `NSOutlineView`, never a source list, with `ThemeTableRowView` rows and `ThemeTableChrome.HostingCell` cells; `DataGridView(themeScope:)`. Window: `ThemeWindowBackdrop` and `DetailColumnBackdrop` (Windows, below).
- **A themed records header is drawn by the theme.** `NSTableHeaderView` paints its own band over anything beneath it, so while `dataGrid.headerBackground` or `headerText` is themed, `ThemeTableChrome` swaps in `ThemeTableHeaderView` and `ThemeTableCornerView`, and puts the table's own back once the theme stops. The data grid's header: `.claude/rules/data-grid.md`.
- **Hold every AppKit carrier strongly**, as a stored property on its owner. Its subscription and its row views keep weak references, so a carrier held only in a local stops at the first theme change.
- **A theme change has to reach the view.** `AppEvents.shared.themeChanged` fires when the active pair changes (a selection, a catalog edit or sync, a draft preview), on a light/dark flip, an Accent or Highlight change, an Increase Contrast toggle and a font change. A scoped carrier subscribes to its scope's `changes`. A SwiftUI view that reads the engine observes it (`@ObservedObject private var themeEngine = ThemeEngine.shared`), because SwiftUI caches `Color(nsColor:)` by object identity; an AppKit view that bakes a color re-bakes on it. Never call `withAlphaComponent` on a system color outside an `NSColor(name:dynamicProvider:)`: it freezes the color.
- **No fixed color on selectable-row text.** A theme color does not turn white on the emphasized selection the way `.primary` does, so `.themeForeground` never goes on a container of selectable rows. Row text keeps a hierarchical style unless the theme also sets that table's selection; `ThemeTableChrome.recordsTextSlot(onThemedSelection:onEmphasizedSelection:highContrast:scope:)` picks a records cell's slot.
- **The window backdrop yields to Increase Contrast** and draws native there, since the format has no increased-contrast variant. Content slots keep the theme.

## Windows and the backdrop

- **The four content windows are `ContentWindow`s**: main (`TabWindowController`), Data File, Compare & Sync and the value viewers. Each holds a `ThemeWindowBackdrop`, which on macOS 26 and later sets `NSWindow.backgroundColor` to `window.background` only while the theme sets it and puts the window's own color back when it stops; the sidebar, inspector and toolbar glass take their tone from it. Before macOS 26 the window keeps its own color.
- **One titlebar policy, in `ContentWindow`.** On macOS 26 and later the titlebar is transparent, so the backdrop reaches the toolbar; in full screen with the toolbar hidden it keeps its background, since it then slides down over the content. Before macOS 26 it stays opaque: a transparent titlebar there swaps its material for a flat fill, which fills chrome. A new content window subclasses `ContentWindow`. Toolbar separators stay each window's own.
- **The detail column sits on `window.background` on every macOS version.** `MainSplitViewController` installs `DetailColumnBackdrop` under the detail panes through `WorkspacePaneHost.installBackdrop(_:)`, so Connecting, Unavailable, the agent and every other state get it. Before macOS 26 it stops below the toolbar, which keeps the system color. The backdrop passes clicks through. `DetailPaneBackdropFill` goes only there; a pane that draws nothing shows it. The Compare & Sync and Data File roots fill with `.themeBackground(.windowBackdrop, native:)`.
- **Never fill chrome.** No fill on the sidebar, inspector frame, toolbar or titlebar, and no `.tint` with a theme color. AppKit keeps its own selection unless the theme sets the selection slot. SwiftLint's `pane_hidden_background` bans `.scrollContentBackground(.hidden)` and `.listRowBackground(` in app code, and `window_background_outside_backdrop` bans a window color write outside `ThemeWindowBackdrop`.

## Engine and catalog

- **`ThemeEngine` owns the selection**: `mode`, `lightThemeId` and `darkThemeId`, set through `apply(mode:)`, `select(lightThemeId:darkThemeId:)` and `apply(mode:lightThemeId:darkThemeId:)`. It never writes settings. It resolves with `ThemeResolver` over the catalog's themes in `ThemeOrdering` order and follows `ThemeCatalog.$themes` itself, so a save, trash, import, sync or file changed on disk repaints with no view involved; a view never asks it to reapply. A burst of catalog or draft changes costs one resolve per run loop turn, in the common modes, because a color well drag runs the event-tracking mode.
- **`ThemeResolver` is pure.** A selected theme that is missing, rejected or of the other appearance draws that slot's default, and the saved id stays, so the theme comes back when its file does.
- **Draft overlay.** `beginPreview(_:)` stands a draft in for the theme with its id until `endPreview(id:)`, so the theme editor repaints the real windows on every change with no file write. A draft no pair slot selects draws nothing.
- **`ThemeCatalog` owns the files.** Built-ins ship as JSON in `TablePro/Resources/Themes` (ids `tablepro.*`, read-only), besides Default Light and Default Dark from the package. User themes are JSON files in Application Support's `TablePro/Themes` folder, resolved through `AppStorageEnvironment`, with ids from `ThemeIdentifier.generated()`. A user theme is its JSON `id`, in whatever file it loaded from. The catalog reloads whenever TablePro becomes active.
- **A file changed on disk wins.** A save, rename or trash of a theme whose file changed or vanished since it was read throws `changedOnDisk` or `deletedOnDisk` and reloads; it never overwrites the file or recreates it under another name. `trash(id:)` moves the file to the Trash, or into the storage environment's own folder when that is isolated, and returns a `ThemeTrashReceipt` that `restore(_:)` takes back. `rename(id:to:)` refuses a taken name (`nameTaken`, case-insensitive); duplicate and import number theirs. Two files with one name show as "Name 2" in the list only, never in the file, so a display fix never syncs.
- **A built-in theme carries its source's license**: an entry in `TablePro/Resources/ThirdPartyLicenses/licenses.yml` and its text in `TablePro/Resources/ThirdPartyLicenses/texts`, checked by `scripts/ci/check-license-inventory.py`.

## The theme editor

- **Settings > Appearance is chrome.** It holds the mode popup on `AppSettingsManager.appearanceMode` ("Applies to this Mac."), the light and dark theme popups, and the themes list: `ThemeLibrarySection` over `ThemeLibraryModel`, which owns every list action and returns typed results.
- **One Theme Editor window per theme.** `ThemeEditorWindows` keeps them, and opening a theme again focuses its window. `ThemeEditorWindowController` is chrome; only its preview wears the theme. `ThemeEditorModel` owns the draft: undo on the window's undo manager with one step per settled change, Revert, a save about 750 ms after a change settles and on close, and the catalog's conflict errors as alerts. A built-in opens read-only, with Duplicate.
- **The preview is the real views.** A read-only `SourceEditor` themed through `EditorThemeFactory.make(resolved:highlightsCurrentLine:highlightsCurrentStatement:)` and a `DataGridView` with `themeScope:`, both on the draft's `ThemeScope.fixed(_:)`, drawn in the draft's appearance. It never takes focus: its editor and grid answer Undo with histories of their own.
- **Set the window's delegate before its content.** A window whose undo manager was read while it had no delegate keeps its own manager and never asks `windowWillReturnUndoManager(_:)`.
- **A slot row** is a `ColorPicker` with `supportsOpacity: slot.offersOpacity` and the slot's `accessibilityLabel`. Its reset shows only while `hasExplicitColor(_:)` is true.

## Sync

- **Each user theme syncs as an `AppSettings` record, category `theme.<id>`**, its payload the canonical bytes from `ThemeFileFormat.encode(_:)`. The catalog marks it dirty on save, rename, duplicate, import and restore, and marks it deleted once the trash has landed (persist, then notify). A load or migration marks nothing. Built-ins never sync.
- **A synced theme is untrusted input.** `ThemeCatalog.applyRemote(category:data:)` checks, in order, the category id (never a built-in id), a 64 KB cap, the nesting depth, a full decode (a newer schema fails here), and the file's id against the category's, and never writes over bytes it has not read. A validation failure is a logged skip. Only a disk failure returns `.failed`, so the coordinator withholds the change token and the pull replays. A remote deletion moves the local file to the Trash through `removeWithoutSync(ids:)`.
- **The theme ids sync; the appearance mode does not.** `AppearanceSettings` (category `appearance`) holds only the light and dark theme ids. `AppSettingsManager.appearanceMode` is device-local (`AppSettingsCategory.deviceLocal`, its own defaults key), and a received `appearance` record never changes it. Fonts are device-local too (`.claude/rules/editor.md`).
- **`SyncCoordinator.themeContentKind` names `ThemeSchema.current`**, so a Mac that upgrades past a schema bump fetches the zone once and picks up the theme records its older build skipped. After the first full pull, only local themes the server lacks are marked dirty, once.

## The lint rule

- **The file list is closed.** SwiftLint's `theme_read_outside_content` names, in its `excluded:` list, every file that may read the theme: a slot, a `palette` or `resolved` read, `activeTheme`, a theme pair, a `ThemeScope`, a carrier, or a helper that reads it (`TreeValueTone.color`, `HighlightedSQLTextView`, `TableProEditorTheme.make()`, `EditorThemeFactory.make(resolved:highlightsCurrentLine:highlightsCurrentStatement:)`, `DetailPaneBackdropFill`, `DetailPaneStatusBarMaterial`). A new content surface joins the list in the same change, and a surface that becomes chrome leaves it. `ThemeBackdropState` and `.paneBarBackground(_:ignoresSafeAreaEdges:)` stay out of the rule's regex, because they are how chrome asks.
