# 0.2.0 delivery scope

The [completion page](bookie-0.2-sprint.md) records the maintainer's delivery decision. This page records the published release boundary; the [backlog](backlog.md) owns subsequent order.

The previous blocker table and exit criteria are retained in the [completion handoff](archive/bookie-0.2-completion-handoff-2026-10-18.md). It is a historical checklist, not fresh test, installed-package or soak evidence. Existing issue-specific evidence and follow-ups remain with their owners.

## Delivery boundary

0.2.0 is the Linux development release for the Arch/Hyprland target, with hotfixes to follow from use:

- PostgreSQL, MySQL/MariaDB and SQLite are the principal database paths; DuckDB is optional. SQL Server, ClickHouse, MongoDB and Redis retain the maturity and restrictions in [known limitations](known-limitations.md).
- GUI and agent operations share the governed policy/audit path. Lost write acknowledgement does not authorize replay, and agent output remains subject to masking.
- Arch/Hyprland is the selected desktop target. Debian/Ubuntu GNOME desktop acceptance and Flathub distribution stay in the post-0.2.0 backlog. The release page also carries a GNOME 50 Flatpak bundle; it does not establish Flathub publication or acceptance against the later GNOME 51 runtime.

## Publication and subsequent work

The app and agentd manifests identify source version `0.2.0`. The [platform guide](platforms.md#published-020-release) lists the published assets and package names. The `bookie` Debian package name landed after the release tag and will be used for a later build.

New upstream adoption, broader engine matrices and development-tooling changes are post-0.2.0 work. They do not reopen this milestone. Preserve exact source/environment evidence when selecting or closing each follow-up.
