# 0.2.0 scope proposal

Draft prepared on 2026-10-11 and reviewed 2026-10-14 against the current branch and blocker ledger. The maintainer decides the scope; each lane confirms its acceptance evidence. Items not listed here as blockers go to the [backlog](backlog.md), and what the application cannot do yet is in [known limitations](known-limitations.md).

## What 0.2.0 promises

A desktop client for Linux that is safe to point at real databases:

- connects to PostgreSQL, MySQL and MariaDB, SQLite and DuckDB files with correct value display and editing; SQL Server, ClickHouse, MongoDB and Redis on a best-effort basis that is stated in the limitations;
- never runs a write the policy would refuse, never replays a write whose acknowledgement was lost, and never shows masked values to an agent;
- targets installation from the Arch package and native Wayland operation on Arch with Hyprland; this is the only desktop acceptance target for 0.2.0. Installed acceptance is still pending (PKG-1). Debian and Ubuntu packages keep being built and tested in CI, but their desktop acceptance (GNOME) comes after 0.2.0. Flatpak is not part of 0.2.0.

Everything else is a later release. The maintainer decided on 2026-10-11 that 0.2.0 is published as a development release for testing on the Arch and Hyprland target; hotfix releases follow from what that testing finds.

## Rules for the freeze

1. After the maintainer accepts this list, no new blocker is added without the maintainer's decision.
2. A pull request in a blocker row is gated on Forgejo on its exact head and merged when GitHub and Forgejo agree.
3. Everything not listed goes to the backlog, with a limitation entry when users can run into it.
