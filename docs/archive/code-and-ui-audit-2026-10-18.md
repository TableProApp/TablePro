# Code and UI audit: BookiE and peer clients

Reviewed 2026-10-18. This is a bounded source audit and improvement proposal. No application was built or launched, no database probe was run, and no current screenshots or measured contrast ratios were collected. Source findings below do not qualify the installed package or change [0.2.0 scope](../bookie-0.2-sprint.md#delivery-boundary).

## Source findings

Priority here means proposed investigation order. It does not assign release severity. A source gap is directly visible in code; a rendered defect needs an observed failing screen or interaction.

| Priority / finding | Evidence and practical risk | Smallest useful next step |
|---|---|---|
| First: pending edits lack a cell-level cue independent of color | [Grid binding](../../apps/linux/app/src/ui/grid/column.rs) gives modified and inserted cells tint classes. [CSS](../../apps/linux/data/resources/style.css) supplies backgrounds at alpha 0.18 and 0.16. The inspected bind path adds no pending-state accessible description. Delete has strikethrough, and the changes bar already shows aggregate state. | Add a persistent cell/row marker and accessible pending-state description, preserving values and selection. Verify modified/insert/delete/error states after virtualized rows are recycled. |
| First: editor scheme selection has no high-contrast branch | [Scheme selection](../../apps/linux/app/src/ui/editor/schema.rs) chooses only `Adwaita` or `Adwaita-dark`; [editor setup](../../apps/linux/app/src/ui/editor/mod.rs) listens to dark changes. No high-contrast listener was found in app source. [Statement highlighting](../../apps/linux/app/src/ui/editor/statement_band.rs) uses fixed gray with alpha 0.12. This establishes a custom-style integration gap, not a measured contrast failure. | Check available GtkSourceView schemes on both supported library floors. Toggle high contrast while both split panes are open; verify text, selection, caret, gutter, statement band and error marks. Choose a supported fallback and own signal teardown. |
| First: loaded-row search does work synchronously in the GTK callback | [Search](../../apps/linux/app/src/ui/grid/row_find.rs) calls `show_matches` directly from `search_changed`. Its 200-hit limit does not bound bytes or time when nothing matches. [RowStore](../../apps/linux/app/src/ui/row_store.rs) returns owned cell values; full-value conversion adds work. Result budgets limit the input but do not establish an interactive latency bound. | Profile no-match searches over representative wide and long-value results. Use bounded main-context slices or a bounded immutable worker snapshot, cancellation and request identity. Preserve draft values, projection semantics and loaded-only scope. |
| Next: large statement buffers are copied before the band limit applies | [Statement band](../../apps/linux/app/src/ui/editor/statement_band.rs) reads the complete buffer in `refresh`; `band_char_range` then checks the 200,000-byte bound. Idle generation checks coalesce callbacks but do not remove the surviving copy. | Measure cursor movement and typing below/above the bound. Check an inexpensive buffer/revision budget before conversion and reuse parsing where possible; preserve Unicode character offsets. No freeze was reproduced here. |
| Next: narrow layout has explicit size constraints | The [editor root](../../apps/linux/app/src/ui/editor/mod.rs) requests 640 logical pixels and its 900px breakpoint hides folding buttons. The [connection popover](../../apps/linux/app/src/ui/app/init_workspace.rs) has a 320px minimum and disables horizontal scrolling; [connection rows](../../apps/linux/app/src/ui/connection_row.rs) include several actions. | Measure the complete layout at the actual minimum width and with large text. Move secondary actions into a menu when needed; retain Run, Stop, transaction state and keyboard access. These constraints alone do not prove clipping. |
| Next: custom pending/focus styles need rendered checks | [CSS](../../apps/linux/data/resources/style.css) fades deleted text, flashes error backgrounds and draws an accent focus ring using GTK node selectors. The fixed connection palette serves identity; [production marking](../../apps/linux/app/src/ui/app/environment_marker.rs) already adds a text badge and window-title marker. | Measure selected/unselected and focused/unfocused states with actual composited backgrounds. Check animation-disabled behavior and retain a persistent error cue. Verify selectors on both library floors. Preserve the existing production text marker. |

BookiE already searches beyond display truncation: `a_long_cell_remains_searchable_beyond_its_visible_preview` in the search module pins that behavior. Full-value editing already has a 1 MiB bound in [the editor helper](../../apps/linux/app/src/ui/grid/full_value_editor.rs). [Font CSS](../../apps/linux/app/src/ui/editor/schema.rs) is scoped to SQL views and validates family names. These need preservation, not duplicate implementations. The tests were read, not executed.

## Proposed audit sequence

1. **Reconcile first, UX.** Use the source pin, open PR file lists, [#1026](https://github.com/cozyGarage/BookiE/issues/1026), [#561](https://github.com/cozyGarage/BookiE/issues/561), APP-MOD and existing B3/B4 issues. For each candidate record existing coverage, missing consumer and one failing user case. This review creates no second status ledger.
2. **Reproduce visual gaps, UX with maintainer desktop acceptance.** Follow the [visual checklist](../manual-verification-app.md#visual-audit-matrix). Start with pending changes, high contrast and narrow layouts. Make one patch per observed defect. Acceptance needs widget behavior plus installed Arch/Hyprland screenshots; use the existing Forgejo gate for code changes.
3. **Measure responsiveness, UX.** Profile loaded-row search, statement bands, completion, lazy restore and large JSON views. Record input bytes/rows, main-context stall, peak memory and cancellation latency. Agree a budget from measurements, then add a failing regression. A new async path must discard obsolete results and release owned work on close.
4. **Probe data and session edges, B3/B4.** B3 owns the MySQL default/DST oracle and page-boundary/export matrices. B4 reviews session retirement, cancellation, policy and terminal audit outcomes where a change touches them. Use unit/sandbox for pure logic and real-engine driver tests for stored values and server state. Record cross-lane handoff before edits.
5. **Select small UX additions.** Dialect type completion is the smallest candidate. Responsive overflow follows observed layout failures. Bounded NOTICE/PRINT output follows the existing backend-then-GTK sequence. Keep ER diagrams, comparison tools and trigger toggles in the existing candidate inventory until a user need, owner and acceptance are selected.

Each implementation packet needs: exact baseline; source/reproducer; owner and allowed files; expected observable outcome; failing-before test; affected test tier; installed evidence when visual; dependency order; remaining limits. Run the [validation playbook](../validation-playbook.md) and serialized gate once the patch is ready. Existing release blockers keep their current priority.

### Coverage for the next code-audit round

These are proposed review surfaces, not findings from this pass. Sample one end-to-end operation at a time and follow it through its existing wrappers instead of auditing each helper in isolation.

| Surface / owner | Adversarial case and observable acceptance |
|---|---|
| Policy, MCP and audit / B4 | Repeat the same denied write through direct SQL, preview, transaction and batch paths. Check scope and allowlist rejection, masked consumer output, and one terminal outcome for denied, failed, cancelled and timed-out operations. Audit failure must not allow execution. |
| Session lifecycle / B4 with UX consumer | Disconnect, close or switch database while connect, query, rollback and metadata work is pending. A stale result cannot change the new tab/session; lost write acknowledgement never permits replay. Verify actual server work stops where cancellation is promised. |
| Decode, edit and export / B3 | Follow NULL, empty text, undecodable values, large numerics, time zones, binary and nested values from the engine through grid edit and export/reimport. Assert native stored kind/value and untouched siblings with an independent oracle. |
| Pagination and retention / B3 with UX consumer | Use zero, page-size-minus-one, exact-page-size and page-size-plus-one rows; duplicate sort keys; changed filters; concurrent table changes; multiple result tabs. Establish the documented consistency model, no accidental skipped/duplicated identities, and aggregate row/cell/byte limits. |
| Durable state and secrets / owning storage/transport lane | Interrupt writes, corrupt or enlarge imported files, lose keyring access and migrate/roll back a profile. Preserve recoverable state and unrelated records; keep credentials, parameters and unmasked values out of logs and diagnostic bundles. |
| App boundaries and dependencies / UX with crate owner | Trace remaining UI imports from services under ADR 0018; check driver-name dispatch against capabilities. Review advisories, licenses, native dependencies and MSRV only when selecting a dependency change; preserve panic containment and static drivers. |

Use the existing test tiers for evidence. Source-only assertions and mutation scores cannot replace native engine outcomes, cancellation observation or a rendered screen. Record the unreviewed paths explicitly when closing a bounded packet.

## Visual acceptance reference

Use native style classes and semantic colors as advised by the [GNOME styling guidance](https://developer.gnome.org/hig/guidelines/ui-styling.html). High contrast is a separate appearance property in [AdwStyleManager](https://gnome.pages.gitlab.gnome.org/libadwaita/doc/main/class.StyleManager.html). As proposed measurement targets for custom content, use 4.5:1 for normal text and 3:1 for meaningful non-text state/focus indicators against adjacent colors, following the relevant [WCAG 2.2 criteria](https://www.w3.org/TR/WCAG22/). Apply their exceptions correctly; decorative connection swatches need not become text. This is a desktop audit target, not a WCAG conformance claim. Contrast and pixel results remain not run at this source pin.
