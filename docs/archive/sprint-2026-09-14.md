## Review evidence and acceptance

Baseline findings: IN-clause renderers omitted dialect-specific backslash escaping.
Lexer probes reproduced incorrect splitting of `SELECT 'a\';b'; SELECT 2`
(MySQL) and nested PostgreSQL comments containing semicolons. Redis temporary
SELECT restoration could be skipped when controlled execution dropped its future.
Export paths disagreed on duplicate names, bytes and fractional times; file writes
ran on GTK and bypassed formula-safe CSV options. Schema refresh lacked
originating connection identity and reloaded tables without views.

Each slice needs a regression before its fix and focused tests afterward.
Fixtures must prove literals stay data, Redis operations stay in their owning
database, failed/cancelled exports preserve destinations, delayed DDL results
cannot affect another connection, and warnings never rewrite executable text.
Test duplicate names `id,id,id_2`, NULL/empty bytes, fractional timestamps, wide
integers/decimals, adversarial CSV text, cancellation and stale async results.

Full-suite testing also exposed a MongoDB numeric conversion regression caused
by arbitrary-precision JSON serialization. Explicit JSON-to-BSON conversion now
preserves integer/filter semantics, with nested-value and wide-integer tests.
Structure editing without a rename now reports success and refreshes metadata.

The file export is incremental **over already loaded rows**, not an unbounded
database stream or snapshot. Cancellation is cooperative until atomic publish.
Catalog transaction tracking governs refresh notifications only; it does not
introduce a new editor transaction/session implementation. SQL warnings never
rewrite text or change policy classification.
