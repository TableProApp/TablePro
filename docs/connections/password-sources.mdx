title: Password Sources
description: Fetch a connection password from 1Password, Vault, AWS Secrets Manager, or any shell command
---

The password field is one of nine answers to the same question, and the other eight never store anything. Point a connection at your secret manager and the password is fetched on every connect, including the reconnects the health monitor makes on its own.

## Choose where the password comes from

The **Password** picker sits in the **Authentication** section of the connection form, under General.

| Option | Needs | Password stored by TablePro |
|---|---|---|
| Save in Keychain | The password | Yes, in the login keychain |
| Ask every time | Nothing | No |
| Shared secret manager command | The command in **Settings > General** | No |
| Shell command | A command that prints the password on stdout | No |
| 1Password | A secret reference, and the `op` CLI | No |
| HashiCorp Vault | A secret path and field, and the `vault` CLI | No |
| AWS Secrets Manager | A secret ID, and the `aws` CLI | No |
| File | A path | No |
| Environment variable | A variable name | No |

Pick **Save in Keychain** unless a policy says otherwise. Pick **Shared secret manager command** when several connections come out of the same vault, which is the case this page exists for.

Everything except Keychain and Ask every time shows the command it will run, and a **Fetch Now** button that runs it once. The password itself is never printed.

### Reaching more than one AWS account

**Profile** names the entry in `~/.aws/credentials` this connection authenticates with, and **Region** overrides the profile's own. Leave both empty to take whatever `AWS_PROFILE` and `AWS_REGION` already select. One Mac with a profile per account needs one connection per database and no shell command:

```
Secret ID   /ops/product/aurora/product-team-6/productadmin
JSON key    password
Profile     hms-product
```

An Aurora secret is JSON holding `username` and `password`, so **JSON key** is what picks the password out of it. Left empty, the whole JSON document becomes the password.

## One command for every connection

<Steps>
  <Step title="Write the command in Settings > General > Secret Manager">
    It runs under `/bin/bash -c` and prints the password on stdout. Surrounding whitespace is trimmed.
  </Step>
  <Step title="Put the connection's own values in with placeholders">
    `op read op://Infra/{name}/password` reads a different item per connection.
  </Step>
  <Step title="Set each connection to Shared secret manager command">
    Nothing else to fill in on the connection.
  </Step>
  <Step title="Click Fetch Now on one of them">
    <Check>The command preview reads back with the placeholders filled, and the result says **Got a password**.</Check>
  </Step>
</Steps>

### Placeholders

| Token | Value |
|---|---|
| `{name}` | Connection name |
| `{host}` | Server host, before any tunnel rewrites it |
| `{port}` | Server port, before any tunnel rewrites it |
| `{user}` | Username |
| `{database}` | Database name |
| `{type}` | Database type, such as `PostgreSQL` |

Each one is quoted as a single shell word, so a connection named `staging db` stays one argument. A brace group that is not in this table is passed through untouched, which leaves `${VAULT_ADDR}` and a `jq '{pw}'` filter working.

The same placeholders work in a per-connection **Shell command**.

## Caching

A fetched password is held in memory for the lifetime set in **Settings > General**, 15 minutes by default, then fetched again. Set **Don't cache** to run the command on every connect.

The cache is dropped when you edit the command, change the lifetime, save the connection, delete it, or quit. Nothing is written to disk, and nothing is synced. **Forget Fetched Passwords** clears it now.

<Tip>A vault that asks for a fingerprint or a 2FA code is worth caching for an hour. The health monitor reconnects without you, and an uncached command puts that prompt on screen while you are somewhere else.</Tip>

## What the command runs as

`/bin/bash -c`, with stdin on `/dev/null`, a 30 second timeout, and output capped at 1 MB. `PATH` gains `/usr/local/bin`, `/opt/homebrew/bin`, `/usr/bin`, `/bin`, `/usr/sbin` and `/sbin` on top of whatever the app inherited. A tool installed anywhere else needs its absolute path.

A tool that wants to prompt on the terminal fails here. Log in to the vault first, or use a token the command reads from a file.

<Warning>The command is run by TablePro, not by your shell. `~/.zshrc` is never sourced, so an alias, a function, or a `PATH` line you keep there does not exist.</Warning>

## Troubleshooting

### Your connections file was changed outside TablePro, so this connection's password source was not run.

`connections.json` is signed, and editing it by hand breaks the signature. Open the connection, change nothing, and save it. The signature is rewritten and the source runs again.

### This connection takes its password from the shared secret manager command, and no command is set.

The connection is on **Shared secret manager command** and **Settings > General** has an empty command. Fill it in, or move the connection to **Shell command** and give it one of its own.

### Password command failed (exit 127): command not found

`PATH` does not reach the tool. Give the absolute path: `/opt/homebrew/bin/op` rather than `op`.

### Password command timed out after 30 seconds

The tool is waiting for something. An expired vault session is the usual reason, because the CLI asks for a login that nothing can answer. Log in from a terminal and try **Fetch Now** again.

### Environment variable … is not set in TablePro's environment.

An app launched from the Dock does not inherit shell exports. Launch TablePro from a terminal, or set the variable with `launchctl setenv`.
