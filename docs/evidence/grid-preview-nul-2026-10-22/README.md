# Long text preview NUL display, October 22

Issue [#1313](https://github.com/cozyGarage/BookiE/issues/1313) tracks the remaining preview path related to [#1249](https://github.com/cozyGarage/BookiE/issues/1249). RowObject samples text values over 8 KiB. The grid preview formatter previously interpolated the sample directly, unlike ordinary text display, which already replaced embedded NUL with U+2400. The raw NUL could therefore reach the GTK text-binding boundary.

The new regression constructs a text preview containing `before\0after`, passes it through CellView::from_preview, and checks both sides of the visible marker and the total-byte suffix. It also checks that the source sample remains unchanged and the preview is not inline-editable. The fully qualified selector failed on the original implementation with raw NUL in the bound string. An earlier command used --exact with an incomplete selector and ran zero tests; that command is excluded from regression evidence.

The fix replaces NUL only in the formatted Text/JsonText preview. It leaves stored values and exact copy/export paths unchanged. No new dependency or GTK widget ownership is introduced. All 29 non-ignored grid display tests passed; the existing isolated widget case was excluded from that selector and exercised by the full GTK tier. All 103 isolated GTK tests and app all-target Clippy passed. Full preflight passed after correcting an invalid ledger ID in the first attempt. Forgejo acceptance remains pending. This is a display-path regression, not a claim of a reproduced database mutation or a measured performance improvement.
