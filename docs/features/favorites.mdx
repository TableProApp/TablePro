---
title: Favorites
description: Pin the databases and tables you keep returning to, save SQL, and link a folder of .sql files
---

The query you retype every Monday is worth saving once. Give it the keyword `dau`, and typing those three letters in the editor expands the whole statement, with the cursor already sitting where the value goes.

The Favorites tab in the sidebar stacks what you have pinned: databases grouped by environment, tables, saved SQL, and a **Team Library** on a Team license. Linked folders of `.sql` files sit beside the saved queries.

## Database favorites

| From | How |
|------|-----|
| The sidebar, in Tree layout | Hover a database row and click its star |
| The database switcher | Press `Cmd+K` or click the database name in the toolbar, then right-click a row |
| The menu bar | **Database > Favorite Database**, on the database you are in |

Start with the star. It is the quickest, and it exists only in the Tree layout (**View > Sidebar as Tree**), so reach for the menu bar when the sidebar is a flat list or your hands are on the keyboard.

A right-click sets the environment in one move: **Add to Favorites > Production**. The star files the database under **Unassigned** instead, and any of the three routes retags it later, where the submenu reads **Environment** once the database is already a favorite. Right-clicking a database that sits inside a multiple selection acts on the whole selection. A filled star then marks the database in the tree and in the switcher.

Favorite databases come first in the Favorites tab, under one row per environment. The **Environment** menu appears once you have a favorite and narrows the list to a single group, and the sidebar's search field filters by database name. Double-click a database, or select it and press `Return`, to switch to it. Right-click for **Use as Active Database**, a different environment, or **Remove from Favorites**; `Delete` removes it too.

Database favorites belong to the connection they were made in and go when you delete it. One whose database has since been dropped stays in the list until you remove it.

## Table favorites

Hover a table row in the sidebar and a star appears at its trailing edge. Click the star to pin the table, or right-click the row and choose **Add to Favorites**. A pinned row keeps its star, filled and yellow, without hovering.

Pinned tables appear under **Tables** in the Favorites tab. Double-click one, or select it and press `Return`, to open it. The right-click menu there has **Open Table**, **Show ER Diagram**, and **Remove from Favorites**, and `Delete` removes the selection.

Table favorites are scoped to the connection, database, and schema, and sync through [iCloud](/features/icloud-sync). One whose table is missing from the database you are browsing is hidden rather than shown broken.

## Recent tables

Turn on **Show recent tables** in [General settings](/customization/general-settings) for a **Recent** section at the top of the object list. It holds the last 10 tables you opened per connection and database, most recent first, and stepping through preview tabs records only the one you stop on. Click a row to reopen the table, or right-click to remove one entry or clear the list. Recents stay on this Mac and survive a relaunch.

## Saving a query

| From | How |
|------|-----|
| The editor | Click the star above it, press `Cmd+D`, or choose **Query > Save as Favorite** |
| Selected SQL | Right-click the selection, then **Save as Favorite** |
| [Query history](/features/query-history) | Right-click an entry, then **Save as Favorite** |
| The Favorites tab | Right-click empty space in the list, then **New Favorite** |

The dialog takes a name, the SQL, and an optional keyword. Select **Global** for a query that names nothing specific to one database, and it is available in every connection. Leave it off and the favorite belongs to the connection you are in, and goes when that connection is deleted, along with its folders.

## Keywords

A keyword is the shorthand you type in the editor in place of the query. Type its first letters, in any case, and the favorite appears in the completion popup under its own name with a star; `Tab` or `Return` inserts the SQL. See [Autocomplete](/features/autocomplete). Two favorites in one scope cannot share a keyword, and the dialog says so as you type.

### Cursor placement

Put `;;` in the SQL to say where the cursor lands after expansion. The marker is removed on insert:

```sql
SELECT COUNT(*)
FROM orders
WHERE orders.;;
```

Accepting that keyword leaves the cursor right after `orders.`, ready for a column name. Only the first `;;` counts; without one the cursor lands at the end.

## Working with saved queries

Double-click a favorite, or select it and press `Return`, to insert it into the editor. **Run in New Tab** on the right-click menu runs it instead, and the rest of that menu is **Insert in Editor**, **Copy Query**, **Edit…**, **Move to** for filing it in a folder, and **Delete**. Arrow keys move between rows, typing jumps to a name, and `Delete` asks before removing the selection.

Folders come from the same background menu. A folder's own menu has **Rename**, **New Favorite…**, **New Subfolder**, and **Delete Folder**, and deleting a folder keeps what was inside it, moved up to the parent level. Drag a saved query or a linked file out of the sidebar to drop its SQL into the editor or another app.

## Team Library

On a Team license the Favorites tab gains a **Team Library** section holding the queries your team published. Double-click one, or select it and press `Return`, to run it in a new tab. To publish your own, right-click empty space and choose **Publish Saved Queries to Team…**, which replaces everything you published before. See [Team Plan](/features/team).

## Linked SQL folders

Link a folder of `.sql` files on disk and they appear in the Favorites sidebar next to your saved queries. The point is a Git repo of shared queries: clone it, link it, and a `git pull` keeps the team's queries current.

<Note>
This is not [Linked Folders](/features/connection-sharing#linked-folders), which watches a folder of shared `.tablepro` connection files.
</Note>

Right-click empty space in the Favorites tab, choose **Add Linked SQL Folder…**, and pick any folder. `.sql`, `.psql`, and `.pgsql` files are indexed, subfolders nest the way they do on disk, and hidden files are skipped. Linked folders are global, so every connection's Favorites tab shows them, and a large repo stays cheap: only the first 4 KB of each file is read to build the sidebar.

### Editing files

Click a linked file to open it as an ordinary editor tab. `Cmd+S` writes back in the encoding the file was read with, detected from the file itself and falling back to UTF-8, then ISO Latin-1. A file that changed on disk underneath you gets the same banner and diff sheet as any other [SQL file](/features/sql-files#when-the-file-changes-underneath-you). Files added and removed outside TablePro reach the sidebar a second after the change.

A non-UTF-8 file carries a yellow warning triangle in the sidebar. Saving keeps its encoding, and a character that encoding cannot represent, an emoji in an ISO Latin-1 file, fails the save with an error rather than dropping the character.

### Frontmatter

Leading SQL comments set the display name, the keyword, and the tooltip:

```sql
-- @name: Active Users (24h)
-- @keyword: dau
-- @description: Daily active users from the last 24 hours
SELECT user_id, last_seen
FROM users
WHERE last_seen > NOW() - INTERVAL 24 HOUR;
```

| Key | Effect |
|-----|--------|
| `@name` | Display name in the sidebar. Falls back to the filename without its extension. |
| `@keyword` | Autocomplete trigger, exactly as for a saved favorite. |
| `@description` | Shown in tooltips. Optional. |

The parser stops at the first line that is not one of these, so they go at the very top; a UTF-8 BOM is handled and the keys are case-insensitive. A file without frontmatter still appears, under its filename and with no keyword. The `;;` [cursor marker](#cursor-placement) works in linked files too.

To change frontmatter without opening the file, right-click the row and choose **Edit Metadata…** The dialog rewrites the leading comment block and leaves the rest of the file, and its encoding, alone.

### Managing linked files

Press `Delete` on a linked file, or right-click and choose **Move File to Trash**: it goes to the macOS Trash and stays recoverable. The same menu has **Open in Editor**, **Edit Metadata…**, **Copy Query**, and **Show in Finder**. A folder's root row carries **Show in Finder**, **Copy Path**, **Disable**, **Reload**, **Add Another SQL Folder…**, and **Remove from Sidebar**. Removing unlinks the folder and leaves the files where they are.

Linked folder paths are the one part of Favorites that does not sync, so each Mac links its own copy of a shared repo.
