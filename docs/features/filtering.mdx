# Filtering

The filter panel builds WHERE clauses without writing SQL. Pick columns, operators, and values visually, or use raw SQL mode for anything the builder can't express. Raw SQL is the default mode. Filters are per-tab, so each workspace keeps its own state.

## Filter Panel

Press `Cmd+F` or click the **Filters** button in the status bar to open the filter panel. The panel opens with one empty filter row ready for input.

Each filter row has:
- A **column picker** (defaults to Raw SQL)
- An **operator picker** (when using column mode)
- A **value field**
- **+** and **−** buttons to add or remove rows

Click **Apply** in the header bar (or press `Enter` in any value field) to activate filters. Click **Unset** to clear all filters and close the panel.

When two or more filter rows exist, an **AND/OR** toggle appears to control how conditions are combined.

## Operators

The filter builder supports 18 operators: equals, not equals, contains, starts with, ends with, greater than, greater or equal, less than, less or equal, IS NULL, IS NOT NULL, IS EMPTY, IS NOT EMPTY, IN, NOT IN, BETWEEN, and REGEX.

Operators without values (IS NULL, IS NOT NULL, IS EMPTY, IS NOT EMPTY) hide the value field.

### BETWEEN Operator

BETWEEN shows two value fields with an "and" label between them. Both values are required.

### IN / NOT IN Operators

Enter comma-separated values to match against a list:

```
value1, value2, value3
```

## Raw SQL Mode

Raw SQL is the default filter mode. Type any WHERE clause condition directly into the value field.

### Using Raw SQL

1. Open the filter panel (`Cmd+F`)
2. The default row is already in Raw SQL mode
3. Type your WHERE clause condition
4. Press `Enter` or click **Apply**

To switch an existing row to Raw SQL, click the column picker and select **Raw SQL** at the top of the list.

**Examples:**

```sql
created_at > NOW() - INTERVAL 7 DAY
```

```sql
LOWER(name) LIKE '%smith%' AND status IN ('active', 'pending')
```

```sql
price * quantity > 1000
```

<Warning>
Raw SQL is injected directly into the WHERE clause. Make sure your syntax is correct for the connected database type.
</Warning>

## Filter Presets

Save your current filter configuration as a named preset for quick reuse.

### Saving a Preset

1. Build your filters in the filter panel
2. Click the **⋯** options menu in the header
3. Select **Save as Preset...**
4. Enter a name and click **Save**

### Loading a Preset

1. Click the **⋯** options menu in the header
2. Select a preset from the menu
3. The saved filters replace the current filter list

### Managing Presets

| Action | How |
|--------|-----|
| Load | Click the preset name in the ⋯ menu |
| Delete | Select **Delete Preset** > click the preset name |
| Overwrite | Save a new preset with the same name |

Presets are stored via UserDefaults and persist across sessions.

<Note>
After loading a preset, click **Apply** to activate the filters.
</Note>

## SQL Preview

See the exact WHERE clause that will be sent to the database before applying.

1. Build your filters
2. Click the **⋯** options menu in the header
3. Select **Preview Query**
4. A sheet displays the generated WHERE clause

## Per-Tab Filter State

Each tab maintains its own independent filter state. Switching between tabs preserves each tab's filters, applied state, and panel visibility.

Tables with active filters (or sorting/edits) open in a new tab when you click another table in the sidebar, preserving your filtered view.

## Filter Settings

Click the **⋯** options menu > **Filter Settings** to configure:

| Setting | Options |
|---------|---------|
| Default Column | Raw SQL (default), Primary Key, Any Column |
| Default Operator | Equal (=), Contains |
| Panel State | Always Hide (default), Always Show, Restore Last Filter |

When "Restore Last Filter" is enabled, reopening a table restores and applies the last-used filters for that table.
