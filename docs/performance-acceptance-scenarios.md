# Performance and acceptance scenarios

Reviewed against Linux source `583c2441957ad2d719762b12c3e6acb9d0cc181a` on 2026-10-24 for [#1563](https://github.com/cozyGarage/BookiE/issues/1563). This matrix reuses existing tests and evidence. It proposes no new release gate and does not claim the unautomated cases are complete.

## Evidence rules

- Keep deterministic limits in unit or GTK tests: retained pages and bytes, row ranges, exact values, explicit terminal outcomes, callback counts and released owners.
- Keep elapsed time, CPU and process memory as host measurements. Record the executable SHA, source revision, toolkit, display backend, fixture version, row and cell sizes, warm-up, repetitions and concurrent load. Report every sample or median and range; do not turn a single host observation into a cross-host limit.
- Check correctness on every measured run. A fast partial result, missing rows or a clean cancel label is not a performance pass.
- Store reviewed summaries under `docs/evidence/<topic>-<date>/`. Keep transient raw output in ignored `target/quality/`; do not cite `/tmp` as durable evidence.
- A fixed observation window cannot prove leak freedom or a permanent memory plateau. Separate RSS/PSS from deterministic ownership and retained-data measurements.

## Current selection

Use deterministic contracts in the normal Forgejo unit and gtk-widgets tiers. Use the existing synthetic profile when comparing grid changes. Run PostgreSQL, multi-cycle lifecycle and installed Wayland scenarios as explicit investigations until a maintained fixture command, correctness oracle and reviewable evidence record exist. Do not add a nightly job just to collect noisy resource numbers.

The measured large-query issues remain separate work items: [#1272](https://github.com/cozyGarage/BookiE/issues/1272) and [#1523](https://github.com/cozyGarage/BookiE/issues/1523) concern PostgreSQL streaming; [#1299](https://github.com/cozyGarage/BookiE/issues/1299) concerns large SQL editor input; [#554](https://github.com/cozyGarage/BookiE/issues/554) and [#1032](https://github.com/cozyGarage/BookiE/issues/1032) track broader streaming and retained-owner limits. This matrix does not close those issues.

The deterministic performance guards were added in [#1559](https://github.com/cozyGarage/BookiE/pull/1559); this matrix reuses them instead of adding overlapping tests. [#782](https://github.com/cozyGarage/BookiE/issues/782) tracks coverage evidence that is still missing for installed-app and GTK accessibility behavior. The external-client checklist in [#790](https://github.com/cozyGarage/BookiE/issues/790) is closed; its cases are inputs for reproduction, not evidence of current defects or a request to duplicate its tests.
