# TablePro Linux dependency review

**Date**: 2026-09-14  
**Question**: are the current and planned dependencies standard, well-known and maintained, so the project does not build up tech debt?  
**Inputs**: the workspace manifests and Cargo.lock after step 1 of the remediation plan, and the dependency decisions in [plan-2026-09-14-audit-remediation.md](plan-2026-09-14-audit-remediation.md)

Each domain was researched against crates.io, GitHub and upstream source, then fact-checked by an independent reviewer that re-queried the numbers and challenged every verdict.

## Verdict

Most of the dependency set already meets the owner's bar: gtk4/libadwaita/glib/gio/sourceview5, gettext-rs 0.8, oo7, sqlx 0.9 (MySQL, SQLite), the official clickhouse crate, rustls with aws-lc-rs, deadpool, sqlparser 0.63, chrono, serde, thiserror, async-trait, tracing, Meson + cargo, cargo-deny, cargo-about and flatpak-builder-tools are all de facto, org-maintained and active. The plan fails the bar in four places. First, it carries two private forks (TableProApp/rust-postgres and TableProApp/tiberius). Second, it keeps Relm4, a niche framework that no GNOME Core or Circle Rust app uses (0 of 31) and that already forces wrapper code and clippy bans. Third, it rebuilds OpenSSH on top of russh (single owner, 8 breaking minors in 9 months) while still spawning ssh and ssh-keygen. Fourth, it adds roughly 20 custom Python scripts and support crates that standard tools already cover. Both forks can go. rust-postgres needs only upstream contributions (#1358 for type OIDs, a new PR for ReadyForQuery status), a SQL-cursor row limit, and exact transaction status tracked per statement with a SAVEPOINT probe. tiberius should be pinned to tiberius-rs main c1d2e741 now, which also clears RUSTSEC-2026-0098/0099/0104 and the archived rustls-pemfile, then moved to upstream main as #440-#449 merge, with money_as_numeric and tls_client_config sent upstream. SSH should run through the system OpenSSH client (ControlMaster, Unix-socket forwards, an askpass bridge). That removes about 25 planned files, the MySQL relay and the ProxyCommand refusal, at the cost of documented Flatpak limits. Relm4 should be replaced with plain gtk-rs subclasses and CompositeTemplate .ui files inside tasks that already rewrite those files. Hand-rolled code that has a mainstream replacement should be replaced: csv::Writer for CSV, deadpool-postgres, tokio-postgres-rustls (after a small upstream OID PR), rustls-platform-verifier where a ClientConfig can be injected, num-bigint, postgres-types/postgres-protocol decoders, and nextest/lychee/cargo-about templates/committed debian and spec files for tooling. Custom code stays only where a hard requirement has no mainstream answer: SqlDecimal, client-side script directives, per-engine SQL dialects, the health state machine, the OpenSSH bridge, and small interim shims each tied to a named upstream PR. Several verification corrections change the plan text itself. The flatpak-builder-lint call needs --exceptions. Accessibility tests need GTK_A11Y=test. GLib keeps an existing file's mode, so an explicit chmod 0600 is needed. /reconcile/conflicts[21], [29], [35] and [39] must be rewritten, or the fork, Relm4 and russh decisions survive. Finally, add Dependabot or Renovate and a dated watch list, so pins and interim shims do not quietly turn into permanent debt.

## Custom code that stays, and why

- `crates/core value SqlDecimal (FB-C2) and PG numeric_wire/interval_wire FromSql impls, SqlTime (24:00:00), timetz`: PG NUMERIC needs NaN, ±Infinity and 131072 digits. rust_decimal caps scale at 28 and bigdecimal has no NaN. postgres-types has no numeric or interval type, and its NaiveTime decode wraps 24:00:00.
- `crates/core/src/script client-directive planner (GO [n], DELIMITER, psql routine bodies, SQLite trigger bodies); the full lexer only if the sqlparser spike fails`: No Rust crate implements client-side splitting. sqlparser has no GO or DELIMITER tokens, no byte offsets, and errors on unterminated input. pg_query is PostgreSQL-only with a C/bindgen build.
- `Per-engine SqlDialect/DdlDialect for MySQL, SQLite, SQL Server (FB-D9, FB-D10, W3-12)`: sea-query has no open-source SQL Server or ClickHouse backend and cannot express MySQL MODIFY, SQLite rebuilds or MSSQL default-constraint handling.
- `HealthPolicy reconnect state machine (W4-05)`: backoff is unmaintained (RUSTSEC-2025-0012). Retry combinators do not model Probe/Reconnect/Wait/Park with generations.
- `crates/app i18n gettext_f/ngettext_f/pgettext_f`: formatx is positional only and i18n-format is niche. Fractal uses the same ~20-line helper.
- `deadpool Manager impls for sqlx-mysql and tiberius`: No maintained deadpool manager exists for sqlx-mysql. deadpool-tiberius is niche and bb8-tiberius is stale. Each impl is ~30 lines on the documented trait.
- `OpenSSH transport glue: askpass helper and peer_cred socket bridge, ControlMaster lifecycle, exit/stderr classification, host-key prompt text detection`: The openssh crate supports password-less auth only and has no ask path. openssh-mux-client has no stdio forward. The askpass protocol is the OpenSSH-provided integration point, and Zed uses the same pattern.
- `ClickHouse Unix-socket connector (tower Service<Uri> -> TokioIo<UnixStream>) for SSH forwards`: hyper-util has no Unix connector. hyperlocal 0.9.1 (2024-07-22) is stale with a single owner. ~15 lines.
- `PostgreSQL transaction status tracker + SAVEPOINT probe; cursor row-limit flight; COPY FROM STDIN refusal (interim until upstream status PR)`: No maintained Rust PG crate exposes ReadyForQuery status publicly (tokio-postgres drops it; sqlx keeps in_transaction pub(crate)). Upstream has no text portal.
- `Direct TCP dialer on tokio + socket2 (sequential, per-address timeout, keepalive/TCP_USER_TIMEOUT) for engines that take injected streams`: Direct use of standard tokio and socket2 APIs, the same as tokio-postgres internals. hyper-util's legacy HTTP connector is not a DB dialer.
- `TLS: no-hostname ServerCertVerifier wrapper for verify-ca / TrustServerCertificate semantics, plus the observed-certificate verifier`: rustls-platform-verifier has no chain-only mode. sqlx keeps an equivalent NoHostnameTlsVerifier internally.
- `crates/drivers/sqlite autocommit.rs single unsafe sqlite3_get_autocommit (tracked interim)`: sqlx keeps in_transaction pub(crate), and is_in_transaction misses raw BEGIN. Remove when an upstream LockedSqliteHandle accessor ships.
- `ClickHouse 'Code: N' prefix parse`: clickhouse 0.15.2 exposes only Error::BadResponse(String). Replace when an upstream structured code lands.
- `CSV formula neutralisation transform; one core hex helper; PersistDebouncer on glib timeout; file_set_contents_full wrapper with explicit chmod 0600`: Small value transforms on platform primitives. The hex crate has not released since 2021 and const-hex is single-owner. GLib preserves an existing file's mode.
- `Temporary MySQL system-CA PEM bundle (only if system-store corporate CAs must work)`: sqlx-core 0.9 aws-lc-rs TLS always seeds webpki roots and accepts CA only as PEM. Remove when sqlx #4045 lands.

## Open risks

- OpenSSH transport: stderr and prompt-text classification is not a stable API (LogLevel, locale, future wording). It needs pinned format tests against the OpenSSH shipped in CI and in GNOME 50. In Flatpak, ProxyCommand and Match exec tools, host /etc/ssh and FIDO file keys do not work; agent-held FIDO keys are unverified at runtime.
- tiberius 0.13 release depends on Prisma-era crates.io owners working in spare time; the stack is 23.5k lines, partly agent-authored and unreviewed. Once RUSTSEC advisory-db#3148 / GHSA-vch9-whpx-g727 is published, cargo-deny fails on any pin before #443 unless a time-limited ignore is documented.
- rust-postgres review latency (#1358 unanswered since 2026-05-29) may keep editor columns text-typed for a long time. The SAVEPOINT probe writes an ERROR line to server logs on each idle probe, and statement-class tracking must be proven for CALL/DO with transaction control.
- The PostgreSQL cursor path changes planner behaviour (cursor_tuple_fraction 0.1), falls back under PgBouncer statement pooling, and loses COPY TO STDOUT result display until upstream exposes CopyData.
- sqlparser breaks its API every 3-4 months, and the shared ScriptLexer spike may fail. The fallback is a documented custom lexer that must then be maintained against five dialects.
- Relm4 removal touches 28 of 43 app files. If not folded into W4/W9 rewrites it could stall mid-migration with two UI paradigms coexisting.
- Trust sets differ per engine (MySQL seeds webpki roots, SQL Server uses tiberius roots) until sqlx #4045 and tiberius tls_client_config land; inside Flatpak only the runtime CA bundle is visible (freedesktop-sdk #1905).
- tokio-postgres-rustls, sqlformat, cargo-shear, libgssapi and gettext-rs have concentrated maintainership. Exit costs are low but must be watched.
- sqlx-mysql direct TCP has no keepalive until #4355, so dead peers are detected only by the health probe and login deadlines.
- sqlx-sqlite unbundled forces libclang at build time for every build, and the direct libsqlite3-sys range can hold the graph back if it is not widened with sqlx patch releases.
- Ubuntu 26.04 rustc 1.93 is below sqlx 0.9's MSRV 1.94, so the .deb must be built with rustup and cannot enter a PPA or the Debian archive.
- Several claims remain unverified: FIDO via host agent in Flatpak, the exact merge timing of tiberius #442/#443, whether KILL QUERY accepts server-side parameters, and compression behaviour of fetch_bytes with lz4 disabled.

### PostgreSQL driver and connection pooling

PostgreSQL stack review, 2026-09-14. You can meet this domain's requirements without a TableProApp fork of rust-postgres.

**Recommended stack, all from crates.io**
- tokio-postgres 0.7.18, postgres-types 0.2.14 and postgres-protocol 0.6.12.
- deadpool-postgres 0.14.2 over deadpool 0.13.1. It already takes a custom `Connect`, so `connect_raw` over the tablepro-net stream plugs in. This replaces the planned PgManager written directly on deadpool.
- tokio-postgres-rustls 0.14.0 with the aws-lc-rs feature. It already does tls-server-end-point channel binding over any stream. This replaces the planned hand-written connector and the x509-cert 0.3 code.
- Replacing sqlx-postgres with tokio-postgres is right. In sqlx-postgres v0.9.0, process_id and secret_key are private (connection/mod.rs:49-56) and `in_transaction` is `pub(crate)` (line 143). So it has no CancelRequest and no transaction status. sqlx stays for MySQL and SQLite.

**The three fork commits, checked against upstream**
1. **Column type OIDs.** Upstream already has this in flight: issue #1329, PR #1338 (OID only) and PR #1358 (OID plus type modifier). #1358 has been waiting on maintainer review since 2026-05-29. Nothing in the plan uses table_oid or column_id except the fork's own tests. Help land #1358 instead of writing a competing commit. Until it ships, single statements get types from upstream `Client::prepare`, which describes without executing. Scripts show text columns.
2. **Transaction status.** No maintained Rust PostgreSQL crate exposes this publicly. Upstream `simple_query.rs` drops the ReadyForQuery status byte, `check_connection` and `query::sync` discard it too, and no issue or PR asks for it. This is the one real hard gap. Least-debt path: file a small additive PR upstream. Meanwhile, either report a conservative Idle/Unknown state, or pin to the upstream PR ref (`rev = "refs/pull/N/head"`, which Cargo documents) with a removal gate. No TableProApp repository either way.
3. **Row-limited text portal.** Drop it. The standard SQL cursor path does the same job: `DECLARE ... NO SCROLL CURSOR` plus `FETCH FORWARD n` over upstream `simple_query_raw`, inside a BEGIN/COMMIT the driver owns. psql up to 16 used this exact pattern for FETCH_COUNT. Upstream is also least likely to accept a text portal: the library is designed around binary results, and sfackler said a text API would be awkward (#882).

**Maintenance and precedent**
- rust-postgres ships about every quarter: 0.7.14 on 2025-09-25 through 0.7.18 on 2026-06-12. It had 56 merged PRs in the last year. Effectively one active maintainer (paolobarbolini wrote 109 of 135 commits since 2025-09-01), and review is slow.
- Real open risk: an upstream deadlock in `query_typed` when a result has non-built-in types (#1348, #1349, open since 2026-05-11). The plan's pipelined workspace reads can trigger it on tables with enum, citext or PostGIS columns. It needs a workaround and a test.
- Precedent without a fork: Tabularis (4.9k stars, Tauri) uses tokio-postgres, deadpool-postgres and tokio-postgres-rustls. rsql uses tokio-postgres 0.7.18. diesel-async uses tokio-postgres. rainfrog and SeaORM use sqlx. Neon, Materialize, Prisma and ReadySet do carry forks, but each has staff to maintain them.

The planned choices hold up: sqlx-sqlite 0.9.0 for the SQLite driver and the history DB, and ClickHouse Inc's official clickhouse 0.15.2 over Client::with_http_client. Every serious alternative is weaker on adoption or maintenance: klickhouse (one maintainer, 4 reverse deps), suharev7/clickhouse-rs (last push 2024-07-16), clickhouse-arrow, libsql/turso (a SQLite fork and a beta rewrite), and tokio-rusqlite (a personal repo). rusqlite is as mainstream as sqlx and has better APIs for this job: safe InterruptHandle, is_autocommit and txn_state. It cannot join the graph today, though. sqlx-sqlite 0.9.0 requires libsqlite3-sys <0.38 and rusqlite 0.40 requires ^0.38.2, and both link sqlite3. The fix (#4402) was merged to sqlx main on 2026-09-09 but is not released. The plan still carries real debt in this domain: (1) one unsafe sqlite3_get_autocommit call plus a direct libsqlite3-sys pin, because sqlx keeps its own in_transaction() crate-private and its public is_in_transaction() only counts sqlx-managed BEGINs; (2) a hand-rolled CREATE INDEX key splitter where the already-planned sqlparser 0.63 parses CreateIndex; (3) keeping escape_bind_markers and a custom line reader after clickhouse 0.15.2 added Client::query_raw() and BytesCursor implements AsyncBufRead; (4) sqlite-unbundled turning on bindgen, which makes libclang a build dependency even with Kerberos off. Also: clickhouse 0.15.2's new fetch_native cannot yet replace JSON decoding. It lacks Decimal, the Date/DateTime family, Enum, Int256, Variant, Dynamic and JSON, and it rejects invalid UTF-8. For future engines: use redis-rs, not fred (fred's last release and push were 2025-02-27, and an open issue asks if the repo is dead); use mongodb with the rustls-tls-aws-lc feature (the default feature uses ring, which FD-D10 bans); use duckdb from the duckdb org and scylla from the ScyllaDB org. Oracle has no mainstream option: the oracle crate has one maintainer, last released 2025-01-02, and needs the proprietary Oracle client.

### SSH tunnels, TLS, networking

Domain: SSH tunnels, TLS, networking. The TLS base is sound: rustls 0.23, aws-lc-rs as the only provider, tokio-rustls 0.26 and socket2 are all de facto, rustls-org or rust-lang crates. The SSH design is the main tech-debt risk in the plan.

The plan already makes the system OpenSSH client a hard runtime dependency (`ssh -G` in W1-01; `ssh-keygen -F` and `-Q` in W1-02). It then re-implements OpenSSH on top of russh anyway, in about 25 new files:
- ssh_config token expansion;
- the pubkey_prepare auth order from sshconnect2.c;
- jump-chain building from ssh.c;
- host-certificate checks (sshkey_cert_check_host);
- KRL and known_hosts decisions;
- a known_hosts writer.
It still refuses ProxyCommand. That is the worst of both options: an external binary dependency plus a large custom security surface that has to follow OpenSSH semantics forever.

Checked evidence:
- **OpenSSH is in the Flatpak runtime.** GNOME 50 junctions freedesktop-sdk-25.08.16. That release's openssh.bst moves only sshd, sftp-server, sshd-*, ssh-sk-helper and ssh-copy-id to vm-only, so ssh and ssh-keygen ship in the platform.
- **All prompts can reach the app.** With SSH_ASKPASS_REQUIRE=force, OpenSSH sends every read_passphrase call to SSH_ASKPASS, even without DISPLAY (readpass.c). That includes the host-key confirmation (sshconnect.c:615), passwords, passphrases and keyboard-interactive prompts (sshconnect2.c:2124).
- **Precedents.** GNOME gvfs's sftp backend spawns ssh with ControlMaster auto and shows its prompts through GMountOperation. Zed runs ControlMaster=yes with SSH_ASKPASS_REQUIRE=force and an askpass helper that talks back over a Unix socket.
- **Unix-socket forwards are private by default.** OpenSSH's default StreamLocalBindMask is 0177, so a forwarded socket is created 0600.
- **ConnectTimeout** bounds the TCP connect and the identification exchange (sshconnect.c passes timeout_ms to kex_exchange_identification).

The Rust SSH crates cannot meet the stated requirements:
- **russh 0.63.3:** active and popular, but one crates.io owner, a repo on a personal account, and 8 breaking minor releases from 0.55.0 (2025-12-02) to 0.63.0 (2026-08-21). Its known_hosts module matches only exact and |1| hashed names, with no wildcards, negation, @cert-authority or @revoked. One malformed key line makes the whole check return an error (the parse error is propagated with ?).
- **russh-config:** no Include and no Match (issue #699, open).
- **ssh2-config:** no Match and no tokens.
- **ssh-key:** its known_hosts module only parses (and 0.7 is still a release candidate); it has no host matcher.
- **libssh2:** last release 1.11.1 on 2024-10-16, a blocking C API, and knownhost.c has no marker handling.
- **openssh crate:** slow (last release 2025-12-03, only dependabot commits since March), documented as password-less authentication only, and its mux client has no stdio forward.

Recommendation: make system OpenSSH the SSH transport, driven directly with tokio::process the way Zed does it. Use one ControlMaster per destination, Unix-socket forwards for streams, and an askpass bridge into the existing CredentialPrompter and AdwAlertDialog. Then delete the re-implementation. Keep russh 0.63.3 only as the interim fix for RUSTSEC-2026-0153/0154 until the switch.

The same change removes the custom MySQL relay for SSH, because ssh owns the private socket. For direct MySQL, sqlx-mysql 0.9.0 keeps do_handshake private and has no keepalive; transact-rs/sqlx PRs #3559 and #4355 (keepalive for MySQL and PostgreSQL) are still open. Narrow the requirement to the health probe, contribute to #4355, and do not keep a relay.

Networking:
- Happy Eyeballs is not standard for database clients. libpq tries addresses in order with connect_timeout per address, and tokio's TcpStream::connect is sequential.
- If it stays, hyper-util's HttpConnector (already in the graph through clickhouse) provides it, plus keepalive, TCP_USER_TIMEOUT, nodelay and connect timeout, with enforce_http(false). That replaces the hand-rolled race and SocketTuning.
- tokio-happy-eyeballs and happy-eyeballs are niche or stale.

TLS:
- The rustls project tells users to prefer rustls-platform-verifier over rustls-native-certs. On Linux it is rustls-native-certs 0.8 plus rustls-webpki, adds a CA file with `new_with_extra_roots`, and reqwest 0.13 uses it by default. Use it wherever a ClientConfig can be injected (PostgreSQL, ClickHouse, SQL Server). Keep rustls-native-certs only to build the PEM bundle sqlx-mysql needs; sqlx 0.9 has no aws-lc native-roots feature and always seeds webpki-roots.
- Drop the planned direct union with webpki-roots.
- Replace the hand-rolled PostgreSQL TlsConnect and tls-server-end-point binding with tokio-postgres-rustls 0.14. It is generic over the stream and computes SHA-256/384/512 bindings.
- Replace the hand-rolled PEM encoder with the pem crate.
- Flatpak caveat that no crate fixes: file-based trust readers see only the runtime's CA bundle. Host CAs exposed through p11-kit are invisible to them (freedesktop-sdk issue #1087, open). Document it and rely on the CA file row.

### Build, packaging, CI and test tooling

Scope: build, packaging, CI and test tooling for TablePro Linux. The plan's main tool choices are the standard ones, and I recommend keeping them: Meson with a cargo custom_target (the Snapshot, Loupe, Fractal, Amberol and gnome-tour shape), glib-build-tools, flatpak-cargo-generator, flatpak/flatpak-github-actions with the gnome-50 image, flatpak-builder-lint, cargo-deny (through cargo-deny-action), cargo-about, testcontainers, the gtk4 test API (#[gtk::test] and test_accessible_*), xvfb-run plus dbus-run-session, and dpkg-buildpackage, rpmbuild and COPR.

The tech debt in this domain is not a fork. It is roughly 16 custom Python scripts and 3 custom Rust support crates, most with their own unittest suites, that re-implement what existing tools or distro conventions already do:
- **Flathub manifest:** render_flathub_manifest.py. Standard flow: the release manifest lives in the flathub/<app-id> repo, as it does for Loupe and Fractal.
- **Package metadata:** license_metadata.py, assemble_debian.py and render_spec.py. Standard replacements: a cargo-about handlebars template, Fedora cargo-rpm-macros (verified in the Fedora 44 specs for loupe, snapshot, papers and glycin), and a committed debian/ directory plus dch.
- **Integration matrix:** integration_matrix.py. Standard replacement: cargo-nextest with `--run-ignored only`, filtersets and test groups, plus clippy ignore_without_reason (Rust 1.88).
- **Doc and process gates:** check-doc-references.py (lychee), check-source-size.py, check-regression-map.py, check-protected-msgids.py and check-clippy-shared-keys.py (one root clippy.toml).
- **Build config:** the tablepro-build-support crate. Standard replacement: Loupe's option_env! config.rs plus meson devenv.
- **Accessibility audit:** stock-internals rules in test-support-gtk pinned to the libadwaita 1.9.3 .ui files. They will break under Fedora 44 (1.9.0) and Ubuntu 26.04 (1.9.1) package %check.

Overall: the plan already uses platform APIs in the right places. Storage paths and durable writes go through GLib user dirs and file_set_contents_full instead of config_io.rs. The flock gate becomes GApplication uniqueness. Logging uses tracing-journald. The i18n placeholder helpers match Fractal's own gettext_f and ngettext_f. OpenSSH semantics come from running `ssh -G` and `ssh-keygen -F/-Q` rather than a Rust reimplementation, and that last choice is the least-debt option: russh 0.63.3 known_hosts.rs handles only plain, hashed `|1|` and `[host]:port` entries, and ssh2-config does not support Match.

The plan does add a lot of new custom code that mainstream tools already cover:

1. **SQL script lexer (W6-05).** A from-scratch lexer for five dialects, although sqlparser 0.63 is already a dependency. Its tokenizer has line/column spans and per-dialect hooks for backslash escapes, nested comments, dollar quotes and `-- ` comment whitespace. Only the client-side directives need custom code: GO, DELIMITER, psql routine bodies and SQLite trigger bodies.
2. **CSV and TSV writer (current export.rs, W5-14, and a duplicate csv_field in storage).** The csv crate covers this: 244M downloads, release 1.4.0 on 2025-10-17.
3. **Happy Eyeballs dialer and socket tuning (W2-10).** hyper-util 0.1.20's HttpConnector, already planned for ClickHouse, has set_happy_eyeballs_timeout, set_connect_timeout, keepalive time/interval/retries, set_tcp_user_timeout and enforce_http(false).
4. **PostgreSQL TLS connector with channel binding (W2-10).** tokio-postgres-rustls 0.14.0 does this: aws-lc-rs feature, tls-server-end-point through x509-cert.
5. **Custom PgManager (W2-12).** deadpool-postgres 0.14.2 has Manager::from_connect with a custom Connect trait, and deadpool 0.13's PoolBuilder has pre_recycle and post_create hooks.
6. **tablepro-build-support crate (W8-14).** Fractal and Loupe generate config.rs with meson configure_file and nothing more.

Verdict challenges:

- sqlparser tokenizer as the W6-05 script lexer (hand_rolled_to_replace + W6-05/W6-17 amendments): replace the custom lexer with sqlparser 0.63 Tokenizer; covers the lexical part of W6-05 to conditional: time-boxed spike first. Keep sqlparser; a raw-text DELIMITER/GO pre-pass stays custom. Checked against the v0.63.0 source, the tokenizer does not cover the plan's lexical rules. (1) MySqlDialect keeps the default supports_dollar_placeholder() == false (dialect/mod.rs:1117; mysql.rs has no override), so '$$' starts a DollarQuotedString (tokenizer.rs:1912-1950). The standard 'DELIMITER $$ ... END$$' idiom would be swallowed as one string token unless DELIMITER regions are cut and matched on raw text before tokenizing. (2) '#' comments are only recognised for Snowflake|BigQuery|MySql|Hive (tokenizer.rs:1719), but ClickHouse's own lexer treats '# ' and '#!' as comments (src/Parsers/Lexer.cpp:383-389). (3) A LexicalSettings wrapper Dialect must override Dialect::dialect() to return the wrapped TypeId (dialect/mod.rs:209, upstream test parse_with_wrapped_dialect). Otherwise dialect_of! checks silently turn off MySQL '#' comments, B'' strings (1085) and PostgreSQL \r comment termination (2059). In its favour, tokenize_with_location_into_buf keeps the tokens produced before an error (tokenizer.rs:952-955), so partial input works. Net: reuse is plausible but not a drop-in. The amendment should list these pre-passes and dialect workarounds, and should not delete string_quote/line_comment_prefix until a fixture corpus passes.
- csv (W5-14 amendment: narrow IfNeeded to RFC 4180 Necessary): add; drop forced quoting of neutralised values to add, but keep forced quoting: use QuoteStyle::Always whenever sanitize_formulas is on, or keep the 3-line quote_field for that path. OWASP's CSV Injection guidance says to 'Wrap each cell field in double quotes' and 'Escape every double quote'. export.rs:218-223 quotes neutralised values on purpose so the leading apostrophe stays data. - tokio-postgres-rustls: add (drop custom channel_binding.rs and x509-cert) to add after an upstream PR, and put on the watch list. Single maintainer (jbg 54 contributions, 42 stars; 14.28M downloads, 102 reverse dependencies). Its digest map (src/lib.rs:109-126) lacks md5WithRSA, ecdsa-with-SHA1 and ecdsa-with-SHA512, which FC-D23 and PostgreSQL be_tls_get_certificate_hash handle. A server certificate signed ecdsa-with-SHA512, common under P-521 CAs, gets no SCRAM-SHA-256-PLUS binding, and channel_binding=require fails. Least-debt path: send the three-OID PR upstream, pin to that release or commit, then delete the custom module. It also pulls x509-cert 0.2, not 0.3.

- rustls-platform-verifier: avoid (reason: sqlx-mysql accepts CA only as PEM) to avoid for now; revisit when sqlx PR #4045 lands. Then every engine could share one mainstream verifier (Verifier::new_with_extra_roots, verification/others.rs:35-92, which loads rustls-native-certs on Linux), and SystemTrustSource plus the PEM bundle could go. The ADR should cite #4045, not only PEM input.

- hyper-util HttpConnector as the generic DB dialer (W2-10/FC-D6 amendments): keep/adopt; narrow RFC 8305 to RFC 6555 to acceptable, but record GIO GSocketClient as the native alternative and note the legacy-namespace risk. Verified at v0.1.20: all setters exist (http.rs:263-432), the per-address timeout is divided by address count (http.rs:754), and enforce_http(false) accepts any scheme that has a host (http.rs:488-510).
